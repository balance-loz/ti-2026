# Dota Predictor

Автоматическая система прогнозов Dota 2. Она сама находит новые турниры, каждый
день собирает сыгранные матчи, переобучается на них и строит прогноз каждой
серии — от первого матча до чемпиона. Матчи, идущие прямо сейчас, оцениваются по
десяти выбранным героям.

Никаких ручных оценок: всё считается только по статистике.

## Что делает система

**Находит турниры сама.** Раз в час она читает ленту профессиональных матчей
OpenDota. Любая лига, в которой появились матчи, попадает в реестр, получает
человеческое имя, свой slug и собственную страницу `/t/<slug>`. Код про конкретный
турнир нигде не зашит — The International 2026 лежит в архиве наравне с остальными.

**Собирает данные каждый день.** Три задачи работают постоянно: добор свежих
результатов, фоновая догрузка исторического окна и подтягивание пиков/банов для
карт, у которых их ещё нет. Всё идёт через один клиент с дневным бюджетом
запросов, так что live-опрос не остаётся без лимита.

**Обучается сама, на своих данных.** В репозитории нет ни одной обученной
модели: рейтинги команд и модель драфта — это результат работы, а не исходник.
Свежий сервер стартует пустым, собирает матчи и обучает обе модели сам, поэтому
не наследует ничьи чужие числа. Раз в сутки обе переобучаются заново. Новая
версия публикуется только если обошла базовую на отложенной выборке из матчей,
которых не было в обучении; не прошла — работает прежняя.

**Прогнозирует турнир целиком.** Формат восстанавливается по сыгранным матчам
(лента результатов не отдаёт сетку), дальше Монте-Карло доигрывает турнир и даёт
вероятности чемпионства, финала и топ-4. Достоверность определения формата
показана на странице рядом с числами.

**Оценивает live-матчи по пикам.** Пока идёт драфт, опрос учащается до 20 секунд.
Как только обе команды закрыли пятерых героев, вероятность считается по героям
поверх рейтингов команд, **записывается один раз и больше не переписывается**.

## Честность цифр

Это самая важная часть, поэтому она вынесена отдельно.

- Прогноз пишется в журнал **до** того, как появился результат. Повторная запись
  для той же серии и той же модели запрещена на уровне схемы.
- Уже сыгранным сериям прогноз **не проставляется задним числом**. Рейтинги
  обучены на данных, которые этот результат содержат, поэтому такая «точность»
  была бы фикцией. Из-за этого точность начинает накапливаться с первого матча,
  который система застала вживую, а у более старых серий в таблице стоит
  «серия сыграна до запуска».
- Серии обнаруживаются по первой сыгранной карте, поэтому часть из них впервые
  видна уже при счёте 1:0. В журнале рядом с прогнозом сохраняется
  `scoreAtFreeze` — видно, при каком счёте он был зафиксирован.
- Модель драфта проходит гейт против **силы команд**, а не против монетки:
  публикуется, только если герои добавляют информацию сверх рейтинга.

## Текущее качество моделей

Замеры на отложенной выборке (см. `npm run predictor:status`):

| Модель | Что предсказывает | Базовая линия | Результат |
| --- | --- | --- | --- |
| Рейтинги команд | победитель серии | монетка, log loss 0.693 | log loss 0.636, точность ~64% |
| Драфт | победитель карты | сила команд, log loss 0.677 | log loss 0.672, точность ~58% |

Вклад драфта поверх рейтингов небольшой — около 0.004 нат и ~1 п.п. точности.
Это честная величина для Dota: исход карты определяется в основном силой команд,
а не пиками. Парные признаки (синергии и контрпики) на отборе стабильно
проигрывают: их отбрасывает сам подбор гиперпараметров.

## Запуск

Нужен Node 24+.

```bash
npm ci
```

Первичное наполнение базы и обучение (одной командой):

```bash
npm run predictor:bootstrap
```

Свежая установка проходит такой путь сама, без ручных команд — планировщик
запускает те же задачи при старте:

| Когда | Что появляется |
| --- | --- |
| ~1 минута | собственные рейтинги команд, прогнозы серий и турниров |
| ~сутки | собственная модель драфта (нужно 1500 карт с пиками, по 1 запросу на карту) |
| дальше | точность растёт по мере накопления истории |

До появления своей модели драфта live-матчи предсказываются по рейтингам, и на
карточке прямо написано, что draft-модель ещё недоступна.

Если есть архив матчей со старой машины, положите его в `data/import/` —
сервер сам заметит файл, разберёт его и переобучится, никаких команд не нужно.
Локально работает и без переноса: `work/draft-training.sqlite` подхватывается
на месте. Разобрать немедленно, не дожидаясь планировщика:

```bash
npm run predictor -- import
```

Каждый файл импортируется один раз; замените его — импорт повторится.

Затем в двух терминалах:

```bash
npm run api
```

```bash
npm run dev
```

Интерфейс в dev-режиме не проксирует API. Либо поднимите обе части через Docker
Compose, либо укажите адрес API явно:

```bash
NEXT_PUBLIC_API_BASE=http://127.0.0.1:3001 npm run dev
```

## Развёртывание

```bash
cp .env.example .env
nano .env
docker compose up -d --build
```

Сайт откроется на `http://IP_СЕРВЕРА/`. SQLite, кэш OpenDota и обученные модели
лежат в Docker volume `state` и переживают пересборку контейнера.

Обновление:

```bash
git pull
docker compose up -d --build
```

### Про ключ OpenDota

Бесплатный тариф работает без ключа, но жёстко ограничен: около 2000 запросов в
сутки и агрессивный троттлинг. Полная догрузка истории на нём растягивается на
несколько дней — это нормально, задача сохраняет курсор и продолжает с того же
места после перезапуска. С ключом (`OPENDOTA_API_KEY`) она укладывается в часы.

## Команды

Все ручные операции — через один CLI:

```bash
node scripts/predictor.mjs <команда>
```

| Команда | Что делает |
| --- | --- |
| `status` | состояние базы, моделей, точности и бюджета запросов |
| `bootstrap` | полное первичное наполнение и обучение |
| `discover` | поиск новых турниров и проставление имён |
| `collect` | добор свежих завершённых матчей |
| `backfill` | фоновая догрузка исторического окна |
| `drafts` | подтягивание пиков/банов для карт без них |
| `sync` | полная перезагрузка активных турниров |
| `rebuild` | пересборка серий и агрегатов из сохранённых карт |
| `train` | переобучение рейтингов и модели драфта |
| `forecast` | пересчёт прогнозов (`--slug <slug>` для одного турнира) |
| `live` | разовый опрос идущих матчей |
| `resolve` | закрытие прогнозов, у которых появился результат |

## Как это устроено

```
server/
  app.mjs              HTTP API и запуск планировщика
  core/
    db.mjs             схема SQLite, все таблицы с league_id
    opendota.mjs       единственная точка выхода в API: очередь, бюджет, троттлинг
    tournaments.mjs    реестр турниров, сборка серий из карт
    ratings.mjs        рейтинги команд, walk-forward отбор модели
    draft-model.mjs    обучение модели драфта поверх силы команд
    predictions.mjs    журнал прогнозов: заморозка, закрытие, точность
    format.mjs         определение формата турнира и Монте-Карло
    live.mjs           идущие матчи и прогноз по пикам
    scheduler.mjs      фоновые задачи
  jobs/
    collect-history.mjs сбор истории и пиков
    forecast.mjs        пересчёт прогнозов турниров
app/
  page.tsx             список турниров
  t/[slug]/page.tsx    страница турнира
  live/page.tsx        матчи в прямом эфире
  model/page.tsx       состояние моделей, задач и точности
```

Переиспользованы из прошлой версии проекта: `server/team-model.mjs` (рейтинговые
семейства и пересчёт между Bo1/Bo3/Bo5), `server/draft-inference.mjs` (вывод по
героям) и `server/live-map-prediction.mjs` (поправка по ходу игры).

## Наследие TI 2026

Прошлая версия была рассчитана на один турнир. Её модули и тесты сохранены:
страницы `/combined`, `/admin`, `/intel` и старый `server/api.mjs` остались в
репозитории, но новым API не обслуживаются и из навигации убраны. Данные TI 2026
доступны как обычный архивный турнир на `/t/the-international-2026-19719`.

Старый конвейер доступен под префиксом `legacy:` в `package.json`.
