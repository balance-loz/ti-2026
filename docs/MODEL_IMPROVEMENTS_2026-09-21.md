# Улучшения моделей и проверки качества — 21.09.2026

HTTPS намеренно не изменялся: по запросу работа ограничена моделями, честностью их оценки и турнирной симуляцией.

## Что исправлено

### 1. Поздние прогнозы больше не улучшают статистику задним числом

В таблицу `predictions` добавлены поля `evaluation_eligible` и `timing_class`.

- `pre_match` — прогноз серии, зафиксированный по официальному расписанию до старта; участвует в accuracy, Brier и log-loss.
- `draft_on_time` — прогноз карты после полного драфта, замеченный не позже `DRAFT_FREEZE_MAX_SECONDS` (по умолчанию 180 секунд); участвует в оценке.
- `in_play_fallback` — серия впервые обнаружена после начала; остаётся в интерфейсе и аудите, но не участвует в метриках.
- `draft_late`/`unverified` — поздняя или не подтверждённая по времени запись; не участвует в метриках.

Старые записи мигрируются консервативно: пригодными признаются только те, для которых сохранён явный признак `frozenBeforeStart`, либо своевременное `gameTimeAtFreeze`. Сомнительные исторические строки не получают статус честного прогноза автоматически.

Draft-прогноз, впервые полученный после разрешённого окна, теперь вообще не записывается как frozen-прогноз. Он может показываться как текущая live-оценка, но не попадёт в публичный рекорд модели.

### 2. Новая ratings-модель не заменяет лучшую автоматически

Добавлен promotion gate для team/player strength:

- обязательный rolling-origin результат лучше coin flip;
- log-loss не хуже активной модели с учётом `RATINGS_MIN_LOGLOSS_IMPROVEMENT`;
- Brier score не хуже активной модели;
- сравнение выполняется только с моделью, которую текущая БД действительно помечает активной, а не со случайным JSON-файлом на диске.

Не прошедший кандидат сохраняется для анализа, но активный `models/team-ratings.json` не перезаписывается. Параметр `forcePromotion` существует только для явного офлайн-исследования/теста и записывается в метаданные.

### 3. Версии артефактов стали неизменяемыми

ID ratings и draft теперь содержит SHA-256 fingerprint входных данных, конфигурации и результата, а не только дату и число строк. Каждый запуск пишет отдельный файл:

- `models/versions/ratings-<date>-<hash>.json`;
- `models/versions/draft-<date>-<hash>.json`.

`model_versions.artifact_path` указывает на конкретную версию. Активный путь перезаписывается только после успешного gate. Отклонённый кандидат остаётся доступен для аудита и сравнения.

### 4. Draft-модель проверяется с тем же prior, что используется в production

Старый draft backtest вычитал отдельный упрощённый online Bradley–Terry prior, хотя сайт обслуживал прогнозы через team+player strength. Это делало holdout непохожим на production.

Теперь offsets строятся cross-fit способом через тот же класс team+player модели, ту же конфигурацию moderation и составы, известные до начала временного блока. Будущее не попадает в fit. Число временных блоков задаётся `DRAFT_STRENGTH_FOLDS` (по умолчанию 8).

Publication gate draft-модели теперь требует одновременно:

1. log-loss ниже team/player prior на том же holdout;
2. Brier ниже prior;
3. верхнюю границу 95% paired bootstrap интервала ниже нуля.

Bootstrap кластеризован по сериям, а не по картам: карты одной Bo3/Bo5 не считаются независимыми наблюдениями.

### 5. Frozen-объяснение сохраняет реальные факторы schema v2

В frozen snapshot теперь записываются evidence, team/player decomposition, lineup, способ shrink, версия схемы и moderation. Поэтому старый прогноз объясняется теми входами, которыми он действительно был сделан, а не упрощённой реконструкцией только из двух рейтингов.

Блок качества читает `validation.rollingOrigin` для schema v2; прежнее чтение отсутствующего `validation.champion` больше не показывает фиктивные нули.

### 6. Турнирная модель использует опубликованную сетку

Когда официальная playoff topology доступна, участники больше не перемешиваются случайно в каждом прогоне. Применяются seed layout и реальные связи winner/loser между слотами; уже сыгранный результат принудительно используется, если он согласуется с участниками симуляции.

Вероятности champion/final/top4 из этой симуляции заменяют результат старой абстрактной случайной сетки. В payload явно указано, что групповой посев остаётся моделируемым, а плей-офф следует опубликованной topology.

## Развёртывание

При первом запуске `openDb()` автоматически добавит новые столбцы и выполнит безопасный backfill. Ручная SQL-миграция не нужна. После выкладки следует запустить обычный retrain: отклонение кандидата теперь является нормальным результатом и означает, что действующая модель оставлена активной.

В рамках этой задачи production-сервер не перезапускался и HTTPS не настраивался.

## Дополнение 22.09.2026 — пары Swiss, Bo3 и единая страница матча

По результатам проверки интерфейса сделаны ещё четыре изменения.

1. Если организатор опубликовал часть следующего Swiss-раунда, система достраивает ещё неизвестные пары среди оставшихся команд. Оптимизация сначала сводит команды с одинаковым счётом, затем избегает повторных встреч. Команды, уже достигшие указанного в правилах числа побед или поражений, повторно не назначаются. Такие клетки подписаны как предполагаемые: они не выдаются за официальное расписание и не попадают в frozen-метрики.
2. Официальный `best_of` календаря теперь имеет приоритет перед эвристикой результатов. Счёт 1:1 в Bo3 остаётся незавершённой/прерванной серией и больше не превращается в ничью Bo2.
3. Запланированные, предполагаемые и live-матчи получили ссылки на общую страницу матча. Live-карточка теперь содержит явное действие «открыть матч, пики и объяснение».
4. На общей странице одновременно показаны прогноз серии по рейтингу, пошаговые факторы этого прогноза, карты, пики, draft-прогноз и вклад героев. Сценарный прогноз для ещё не утверждённой пары явно помечен как изменяемый, в отличие от зафиксированного pre-match прогноза.

Добавлены регрессионные тесты для достраивания Swiss-пары и запрета ничьей 1:1 в официальном Bo3.
